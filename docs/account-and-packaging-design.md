# 账号、同步与安装包设计

目标：让用户用邮箱验证码注册、密码登录，在不同设备恢复角色、聊天、日程与奖励数据；提供 Android 安装包，并明确鸿蒙版本对应的安装方式。

## 架构

- Node 服务端管理账号、验证码、密码哈希、会话和每个账号的应用快照。原型采用单进程文件数据库，原子写入并保留更新前备份；未来部署多实例时迁移到数据库。
- QQ 邮箱 SMTP 只在服务端发送一次性验证码，授权码从环境变量读取。未配置时明确提示，不把授权码或 DeepSeek 密钥打进前端或安装包。
- 客户端保留当前本地数据作为离线副本。登录时先恢复云端快照；新账号且云端空时迁入本机数据。后续修改自动上传，服务端用 revision 防止另一设备的数据被静默覆盖。退出登录只清除会话，不删除服务器数据。
- 账号 API 与同步 API 分离。生产模式的 AI API 必须要求登录，避免公开消耗模型密钥。开发本机模式仍允许游客体验。
- Android 由现有 Capacitor 工程生成 APK。鸿蒙 4 及更早版本走兼容 APK；鸿蒙 5 及以后需要 DevEco/ArkTS 原生 HAP，单独开发和签名，不能将 APK 重命名使用。

## 验收

1. 错误验证码、重复邮箱、错误密码被拒绝；密码只保存加盐 scrypt 哈希。
2. 登录后用户 A 只能访问 A 的快照；用户 B 不能访问 A 的数据。
3. 服务重启后账号和快照仍在；客户端刷新后能恢复当前账号数据。
4. 修改角色、聊天、任务后自动同步；冲突不静默覆盖。
5. APK 实际完成构建；未完成的 HAP 或服务器部署明确标出。

## 实施顺序

1. 测试驱动实现账号存储、验证码、会话、快照与 HTTP 接口。
2. 接入 QQ SMTP 配置与客户端注册登录、迁移和同步状态。
3. 构建 Android APK、验证安装包存在和签名；检查鸿蒙原生工具链。
